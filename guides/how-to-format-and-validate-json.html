How to format and validate JSON

APIs return JSON as one endless line. Config files break with a cryptic “unexpected token” error. Formatting (pretty-printing) spreads JSON across indented lines so a human can read its structure — and validating tells you whether it is legal JSON at all, and where it breaks if it isn't.

Step by step

1. Open the JSON Formatter. It runs in your browser — don't paste secrets into any online tool, this one included; here, at least, nothing leaves your device.

2. Paste your JSON.

3. Format. Valid JSON comes back indented and readable. Invalid JSON gets a clear error message pointing at the problem instead of a silent failure.

4. Copy or minify. Copy the pretty version for reading and debugging, or minify it back to one line for pasting into a config or request body.

The five mistakes that break JSON

Trailing commas — {"a": 1,} is legal in JavaScript objects and illegal in JSON. The number one culprit.

Single quotes — JSON strings and keys must use double quotes: "name", never 'name'.

Unquoted keys — {name: "x"} is a JavaScript object, not JSON. Keys need quotes.

Comments — JSON has none. A // note inside the file breaks it (some parsers forgive this; the standard doesn't).

Missing or extra brackets — every { and [ needs its partner. Formatting a valid file makes nesting visible; an invalid one usually has a bracket out of place near the error position.

Tips that save you a re-do

Read the error position, then look slightly before it. Parsers report where they gave up, which is often one token after the real mistake — a missing comma at the end of the previous line is the classic.

Format before you diff. Comparing two minified JSON blobs is hopeless; format both, and the one changed value stands out line by line.

Keep a known-good copy. Before editing a config by hand, save the working version. When the edit breaks, you can diff or roll back in seconds.

Frequently asked questions

What is the difference between formatting and validating?

Validating answers “is this legal JSON?” Formatting answers “show it to me readably” — and a formatter can only format JSON that validates. If formatting fails, the error message is the validation result telling you where it broke.

Why does my JSON work in code but fail validation?

Because what you have is probably a JavaScript object literal, not JSON: unquoted keys, single quotes, trailing commas or comments are all fine in JS and all forbidden in JSON. The fix list above covers nearly every case.

Is it safe to paste API responses here?

The formatter runs entirely in your browser, so the JSON never leaves your device. Still, make it a habit to strip tokens and passwords out of anything you paste into any tool, anywhere.
