Contact

Tool requests, bug reports and corrections are all welcome. ToolSprint is a one-person project, so the fastest route is GitHub:

github.com/shaikh1085

Reporting a bug

Open an issue or discussion on GitHub and include:

  • The tool name — exactly as it appears on the site.
  • What you did — the input type (for example, “a 3-page PDF”) rather than the file itself. Please do not attach private files.
  • What happened — the exact error message shown, or what the result looked like.
  • Your browser and device — for example, “Chrome on Android”.

Requesting a tool

Suggest the tool name and one sentence on what it should do. Tools that can run entirely in the browser are far more likely to be added — anything that needs your file uploaded to a server goes against how ToolSprint works.

Frequently asked questions

What is the fastest way to contact ToolSprint?

GitHub — use the button above to reach shaikh1085. ToolSprint is a one-person project with no support desk or contact form, so an issue or discussion on GitHub is the route that actually gets read.

Should I attach my private file when I report a bug?

No. Please do not attach private files. Describe the input instead — for example “a 3-page PDF” or “a PNG photo” — along with the tool name, the exact error message shown, and your browser and device, such as “Chrome on Android”.

What makes a tool request more likely to be accepted?

Keep it to the tool name plus one sentence on what it should do, and pick something that can run entirely in the browser. Requests that need your file uploaded to a server go against how ToolSprint works, so they are unlikely to be added.

Will I get a reply straight away?

Not necessarily. ToolSprint is maintained by one person, so there is no guaranteed response time. Leaving your report as a GitHub issue or discussion keeps it visible and in one place until it is picked up.
