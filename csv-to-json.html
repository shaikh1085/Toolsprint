Frequently asked questions

How are quoted fields with newlines handled?

Properly. The parser reads character by character and tracks whether it is inside quotes, so a line break inside a quoted value stays in that value instead of starting a new record — the exact case that breaks naive split-by-line converters.

What if a row has fewer cells than the header?

Missing cells become empty strings, and extra cells beyond the header are kept under generated names (column_5, and so on). A key is never literally “undefined”.

Are numbers converted to JSON numbers?

No — every value stays a string, exactly as CSV stores it. That is the safe default: IDs like “007” and phone numbers keep their leading zeros.

My file uses semicolons instead of commas. Will it work?

This parser expects commas (the CSV standard). If your export used semicolons — common in European Excel files — re-export with commas, or the whole line will land in one field.
